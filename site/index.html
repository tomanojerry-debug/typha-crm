03 / 工程设计

每一次回答，
都有执行边界。

模型负责理解和生成。
服务端负责权限、状态与执行。

主要持久对话任务的执行路径Home / Ask / Workflow
  1. 01任务入口明确本轮要求与范围
  2. 02持久 Run排队、订阅、取消
  3. 03上下文计划条件、历史与证据
  4. 04受控执行读取、生成、准备草稿
  5. 05提交前复验权限、版本与来源
  6. 06保存与展示回答、状态或草稿
身份与客户权限贯穿读取、执行和提交/正式修改和发送遵循各自确认流程
任务与上下文+

TaskState 保留任务的有效条件，ContextPlan 绑定本轮输入、授权资料与容量摘要。主要持久会话任务共用运行预算，支持取消与结果恢复。

已接入的主要持久对话 Run 默认180秒／8次模型调用；满足上下文、来源和未展示正文等条件时，瞬时模型故障整次最多重试一次。其他入口范围见项目说明。

阅读 Harness 说明 ↗
权限与原文依据+

客户 ACL 是业务资料权限依据，负责人或地区不会自动授予访问权。图谱和向量帮助检索，命中后仍按当前授权与版本回读来源。

对话日志、跨轮任务、本人偏好与客户业务知识分层保存。资料变化或撤权时，旧来源不能继续被当作有效依据。

阅读记忆与来源设计 ↗
验证与质量边界+

工程回归、真实模型试跑和业务语义验收分别记录。虚构夹具验证权限、状态与副作用，评测证据与源码版本绑定。

局部工程通过不等于完整产品质量通过。完整场景覆盖与人工校准的进展，以仓库中的当前记录为准。

查看验证说明 ↗
本机部署与模型费用+

React / TypeScript 前端访问本机 Node.js / Express 服务，业务存储默认使用 PGlite，原文向量使用 pgvector；知识检索可接入 Graphiti 等组件。

企业持有本机业务数据，并自行承担模型 API 费用。执行 AI 任务时，选定的任务上下文仍会发送至所接入的模型服务。
