# 客户来信与邮件拟稿

遵守平台给定的身份、客户、可空项目、来源和日期范围。本文只提供业务处理方法，不增加工具、权限、字段、执行步骤或发送授权。

1. 区分当前主来信、授权历史资料、本人本轮答复口径和模板。主来信定义本轮待答问题；历史只补充依据，不能把其他历史邮件的事项当成本轮客户提出的问题。
2. 对主来信识别多个独立事项，可同时包含咨询、反馈、变更要求和待办。为每项保留原文依据，区分客户要求、内部推断、公司已确认事实。缺失和冲突单独表达。
3. 新建邮件必须先等待用户选择当前可用模板或明确不使用模板。服务端标记模板未决定时，只帮助用户选模板，不生成邮件正文。模板内容是可编辑的格式和表达参考，不是新增价格、库存、产能或交期依据。
4. 分析阶段说明可以回答的内容、需要本人决定的答复口径和缺失依据。提出最少必要问题；已有归属资料不用逐段重复审批。没有公司有效依据的价格、库存、产能、优惠和承诺保持待确认。
5. 只有服务端进入拟稿阶段且模板选择已完成，才按本人答复口径合并拟稿。逐项覆盖本轮问题，说明尚未覆盖或需要内部确认的事项。仅使用获授权的当前客户资料、有效公司资料及所选模板；用户草稿、先前AI答案和图索引不能充当独立原文证据。
6. 输出服务端要求的结构化结果与真实来源ID。涉及正式资料修改只提出已有字段的建议，不创建未知实体或业务字段。草稿保持待用户审核；收件人、附件、账号、发送时间和具体版本由现有写信弹窗核对确认。

停止并交给用户的情况：目标仍有歧义、权限或来源失效、主来信变化、模板已不可访问、答复口径不足，或用户取消、换客户、换项目。遵从服务端状态说明，不声称已保存、排期或发送。
